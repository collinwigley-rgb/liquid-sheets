# Liquid Sheets

A free, open, browser-only auction draft tool for fantasy football. All computation runs client-side. You bring your own projections and league settings. Everything is stored in your browser: no account, no server, nothing uploaded. Closing the tab loses nothing; a one-file save moves it to another device. (It also works with no connection, since there is nothing to connect to.)

**Status: in build (feature-parity pass landed 2026-08-25).** The app runs: setup wizard, one-click Sleeper fetch, universal paste/CSV import, a value board, and a full draft room (The Call with plan-fit, budget envelopes, owner ledger, TEAMS grid, room-pressure strip, flagged players, named bets). Developed in the open. Target: public beta by July 2027, launch for the 2027 draft season.

## Why

The best draft tools of the past (BeerSheets and its descendants) kept dying, mostly over data licensing. Liquid Sheets is designed around that failure mode: it never hosts or redistributes anyone's projections. The tool is the engine, the draft room, and the discipline; the data is yours.

It is derived from a private single-league tool built and battle-tested through the 2026 season, including a full value-based-drafting engine, an auction draft room, and a design doctrine of deliberate parsimony: fewer numbers, each one traceable, adjustments off by default.

## Principles (non-negotiable)

1. No data redistribution, ever. Users bring their own.
2. Client-side everything. No backend, no accounts.
3. Every number traces to an inspectable calculation.
4. Your data stays in your browser. Nothing uploaded; a file you own is the way to move or copy it. Working offline follows from that and remains an acceptance test.
5. Free forever. No monetization.

## Running it locally

It is a static site with no build step. Serve the repo root and open `app/`:

```
./dev.sh          # serves the repo root on http://localhost:8013
```

Then visit `http://localhost:8013/app/`. Everything (your league, sources, runs, sales) lives in your browser's IndexedDB; the gear menu exports and imports a one-file JSON backup.

## Self-hosting the AI copilot (optional, developers)

The hosted app ships with **no AI**: no API key, no toggle, nothing leaves your browser but the projection sources you fetch yourself ([ADR-0006](docs/adr/0006-ai-copilot-self-hosted-companion-not-in-app.md)). The live "reading the room" copilot is available only if you run it yourself:

1. Run the companion server (standard library only, no dependencies):
   ```
   python3 copilot-server/server.py
   ```
   By default it shells out to your local `claude` CLI. See [copilot-server/README.md](copilot-server/README.md) for the API-key transport and all env vars (`PORT`, `ALLOW_ORIGIN`, `COPILOT_MODEL`, `COPILOT_EFFORT`, `COPILOT_TRANSPORT`, `ANTHROPIC_API_KEY`).
2. Point the app at it: set `AI_ENDPOINT` in `app/config.js` to the server's URL (for example `"http://localhost:8017"`).
3. Reload the app. A gear-menu toggle appears (synthesize / complement / off), and the live read fills the staging card when you nominate a player.

All AI content is generated by your own AI under your own account; the app never ships or hosts any. The board and The Call never depend on it.
