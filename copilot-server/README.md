# copilot-server

An optional, self-hosted AI "live read" companion for the static browser
fantasy-football auction app. It is a small, dependency-free HTTP server: when a
player is staged for auction, the app POSTs the context it already computed, and
this server relays a prompt to a model and returns one short action line for the
app's `#liveread` panel.

The hosted static app ships with the AI OFF. This server is what a self-hoster
runs to enable the `#liveread` panel, by pointing the app's `config.js`
`AI_ENDPOINT` at this server's base URL.

All AI content is generated by the operator's OWN Claude access: either the local
`claude` CLI on this machine, or the operator's own Anthropic API key. There is
no shared key and nothing here calls a hosted service on the app's behalf.

## Requirements

- Python 3 (standard library only; no `pip install`).
- One of:
  - the `claude` CLI on `PATH` (default transport), or
  - an `ANTHROPIC_API_KEY` (API transport, or as a fallback when the CLI is
    missing).

## Run it

```
python3 server.py
```

That is the whole command. It binds `127.0.0.1` on the configured port (default
8017) and prints which transport and model are active.

## Environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `PORT` | `8017` | Listen port. Chosen to avoid the app's 8013 and other local servers on 8000/8015. |
| `ALLOW_ORIGIN` | `*` | Value for the CORS `Access-Control-Allow-Origin` header. Set it to your app's origin (for example `http://localhost:8013`) to lock it down. |
| `COPILOT_MODEL` | `claude-opus-4-8` | Model id passed to the CLI (`--model`) or the API (`model`). |
| `COPILOT_EFFORT` | `medium` | Effort level for the CLI transport (`--effort`, e.g. `low`/`medium`/`high`). Ignored by the API transport. |
| `COPILOT_TRANSPORT` | `cli` | `cli` shells out to the local `claude` CLI. `api` calls the Anthropic Messages API over HTTPS. |
| `ANTHROPIC_API_KEY` | (unset) | Required for the `api` transport, and used as a fallback when `COPILOT_TRANSPORT` is `cli` but no `claude` CLI is on `PATH`. |

## Transports

Two documented ways to reach a model. The default matches the personal tool this
is ported from.

1. **CLI (default).** Shells out to the local `claude` CLI, headless, with an
   empty MCP config so cold starts stay fast (the co-pilot uses no tools):

   ```
   claude -p "<prompt>" --model $COPILOT_MODEL --effort $COPILOT_EFFORT \
     --strict-mcp-config --mcp-config '{"mcpServers":{}}'
   ```

   If the `claude` CLI is not on `PATH`, the server falls through to the API
   transport when `ANTHROPIC_API_KEY` is set; otherwise a read returns a clear
   error string that the panel shows.

2. **API (alternative).** Set `COPILOT_TRANSPORT=api` and `ANTHROPIC_API_KEY`.
   The server POSTs to `https://api.anthropic.com/v1/messages` using only the
   Python standard library (`urllib.request`), with headers `x-api-key` and
   `anthropic-version: 2023-06-01`, a single user message containing the prompt,
   and `max_tokens` of 400. It reads `content[0].text` from the JSON response.
   No third-party SDK is imported.

## Endpoint contract

The browser client stages a player, then polls until the matching read is ready.
This mirrors what the app's `stageCopilot` sends.

### `POST /api/stage`

Kicks off a live read and returns immediately (fire-and-forget). The model call
runs on a background thread; a newer stage invalidates an older in-flight read.

Request body (JSON):

```json
{
  "player": {
    "name": "Player Name",
    "pos": "RB",
    "our_value": 34,
    "proj_pts": 245,
    "est_bid": 31
  },
  "mode": "synthesize",
  "call": {
    "verdict": "BUY",
    "worth": 34,
    "plan_cap": 28,
    "room_bids": 31,
    "reasons": ["thin RB supply", "two rivals are RB-full"],
    "slots": [{ "slot": "RB2", "plan": 28 }],
    "bench_per": 1,
    "bench_open": 0,
    "tags": ["target"]
  },
  "brief": "<plain-text board/room summary the client assembles>",
  "roster_fit": "<optional plain-text line, e.g. MY ROSTER FIT: fills my OPEN RB starting slot.>"
}
```

Notes on the fields:

- `player` values are all optional; missing or null numbers are simply omitted
  from the staged-player line. `est_bid` is the client's already-scaled estimate
  of the league bid.
- `mode` is `"synthesize"` (default) or `"complement"`. Synthesize returns the
  single verdict as one bid instruction plus one reason. Complement treats the
  Call as the verdict and adds only what the Call cannot know, or returns
  `no read`.
- `call` is the deterministic verdict card already on the app's screen. An empty
  object is accepted (the block just notes it was not supplied).
- `brief` is a plain-text board/room summary the client assembles. This server
  does not compute it; there is no database here.
- `roster_fit` is optional. When present it is inserted ahead of the Call and is
  governed by the `ROSTER-FIT RULE` in the prompt.

Response:

```json
{ "ok": true, "seq": 7 }
```

`seq` is a monotonically increasing counter. The client remembers it and polls
for the read whose `seq` matches.

### `GET /api/copilot`

Returns the current read state:

```json
{ "seq": 7, "status": "thinking", "text": "", "player": "Player Name" }
```

- `status` is `idle` before the first stage, `thinking` while a read is in
  flight, and `ready` when `text` holds the result.
- The client uses the read only when `seq` matches the value it got from
  `/api/stage` and `status` is `ready`. If `text` starts with `no read` (or
  `no live read`), the panel is cleared.

### `GET /` and `GET /health`

Tiny JSON health check: `{ "ok": true, "service": "copilot-server", ... }`.

### CORS

The static app is served from a different origin than this server, so every
response carries permissive CORS headers and `OPTIONS` preflight is handled. The
allowed origin is `ALLOW_ORIGIN` (default `*`).

## Wiring it to the app

Run this server, then set the app's `config.js` `AI_ENDPOINT` to this server's
base URL (for example `http://localhost:8017`). With `AI_ENDPOINT` set, the app
enables the `#liveread` panel and starts POSTing to `/api/stage`.
